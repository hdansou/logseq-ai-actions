### Added

- **Tone rewrite seed actions** — `rewrite-formal`, `rewrite-casual`, `rewrite-friendly`. Each sits right after `rewrite` in the registry (groups together as `AI: Rewrite*` in the palette) and uses the same `block` scope + `diff-panel` output as `rewrite`. Prompts are tuned for small local models with the "return only" discipline and explicit guardrails against adding new information or changing meaning. Users can add their own tone variants (e.g. `rewrite-academic`, `rewrite-direct`) via Manage Actions without touching the seed set.
- **`rewrite-professional` seed action** — rewrites the block following "Writing the Amazon Way" principles: short declarative sentences in active voice, concrete nouns over vague adjectives, one idea per sentence, and an explicit weasel-word blocklist ("very", "really", "many", "some", "could be", "might", "basically"). Same `block` + `diff-panel` contract as the other tone variants.
- **`extract-image-text` seed action (vision OCR).** Targets the same DB-graph image asset blocks as `image-title`. Extracts all visible text via the configured vision model, parses the response as a nested outline (using the existing `parseOutline`), shows a confirm panel with the indented preview, and on accept appends the tree as new child blocks under the image. Non-destructive — pre-existing children are preserved. The OCR system prompt requires verbatim extraction (no summarising / paraphrasing / translation), uses the standard outline syntax for prose/headings/lists, AND instructs the model to emit well-formed markdown tables with header-separator rows as standalone blocks (NOT nested under bullets). Confirmed working with `qwen3.5:2b`. New regression test asserts the prompt keeps verbatim and table-syntax instructions.
- **`parseOutline` extended with markdown-table support.** A header row starting with `|` immediately followed by a separator row (`|---|---|`, alignment markers like `:--`/`--:`/`:-:` accepted, whitespace OK) is slurped together with any subsequent body rows into a single leaf `OutlineNode` whose text is the multi-line markdown table verbatim. Tables emit as top-level (depth-0) siblings in source order; the stack resets after a table so subsequent indented bullets re-anchor to root. Stray `|` lines that don't form a well-formed table fall through to existing bullet/text handling (no behaviour change). Benefits `outline-replace` / `outline-append` for free — text-action LLMs that happen to generate tables now have those tables preserved as clean Logseq blocks. 9 new unit tests.
- **`runVisionAction` learns to dispatch on `outputMode`.** Existing `picker-replace` flow (image-title) stays put as the default; new `outline-append` branch parses the LLM response, shows a confirm panel preview, and recursively inserts via the existing `insertOutlineTree`. The vision call's `user` text is now mode-aware (a short hint that orients the model on the response shape). No new pure modules; no new UI. Composes from existing primitives.
- **Inline hints under Scope / Output mode / Kind fields** in the Manage Actions editor. Each field now renders a one-line description of the *currently-selected* value (e.g. picking `subtree` shows "The block plus all its descendants, flattened into a Markdown outline."), updating live as the user changes the selection. Same hints render under the read-only built-in inspect view so users can quickly understand what a built-in does without reading the prompt. Three hint maps (`SCOPE_HINTS`, `OUTPUT_MODE_HINTS`, `KIND_HINTS`) in `ManageActionsPanel.tsx`; the existing `Field` component grew an optional `hint` prop. New `.manage-field-hint` CSS class.
- **Manage Actions UI redesign — gallery + inline detail (Mockup C).** Replaces the row-based list with a card grid of all actions (built-ins + user). New states: empty (first-run CTA), Create / Update (single shared form with sensible defaults — `block` / `diff-panel` / `text` and an auto-suggested kebab-case id from the title), View built-in (read-only banner + "Duplicate as user action" escape hatch — creates an editable copy with an auto-incremented `<id>-copy[-N]` id), Validation (per-field red borders + a top error summary that lists every issue with the offending field name; Save remains enabled, but the next click re-renders the summary). Delete is now an in-modal overlay (replaces the browser-native `window.confirm`) and acknowledges the slash/palette no-deregister-API quirk inline. Search filters the gallery by title / id / description / prompt. The pill-style scope/kind selector is now real `<input type="radio">` for accessibility. Reuses existing form classes (`manage-form`, `manage-field`, `manage-input`) so the rewrite stays surgical; new classes added under the existing manage-* namespace (`manage-toolbar`, `manage-grid`, `manage-tag`, `manage-icon-btn`, `manage-empty-state`, `manage-readonly-banner`, `manage-error-summary`, `manage-prompt-wrap`, `manage-prompt-toolbar`, `manage-confirm-overlay`).
- **Theme variables now reference Logseq's CSS custom properties first** (`var(--ls-primary-background-color, #ffffff)`-style), with our previous values as fallbacks. No-op in a cross-origin iframe today (Logseq doesn't propagate these into plugin documents), but if/when the SDK starts propagating them, custom Logseq themes will flow through automatically.
- **Vision support: `image-title` seed action.** Targets DB-graph image asset blocks (those tagged `:logseq.class/Asset` with raster type png/jpg/jpeg/gif/webp). On invocation: validates the block is an image asset → reads bytes via `logseq.Assets.makeUrl(assets/<uuid>.<ext>)` + `fetch` + `FileReader.readAsDataURL` → calls a multimodal completion → parses 3 candidate titles → opens a `ChoicePanel` (1/2/3 hotkeys, Esc cancels, includes a "Keep current title" option) → on accept writes the chosen string to `:block/title` via `updateBlock`. Fails soft with a clear toast on non-image blocks; errors include a hint that the model needs to support images. Backed by a new pure `image-asset.ts` module (8 tests covering shape detection across the SDK's varied property-key serialisations) and a new pure `parse-titles.ts` module (15 tests covering numbered/bulleted/quoted/preambled LLM outputs, dedup, trailing-punct trim, n-cap).
- **`completeVision` provider method** on `LLMProvider` with `CompleteVisionRequest`/`VisionImage` types. Same `/v1/chat/completions` endpoint as `complete`, just a multimodal `messages` body — `[{type:"text"...}, {type:"image_url", image_url: {url: data:image/png;base64,...}}]`. 6 new tests (body shape, auth, missing image, HTTP error, missing content). Confirmed working with Ollama `qwen3.5:2b` and `qwen3.5:0.8b` (Alibaba's unified vision-language line) per Q3 confirmation; works equally with Llava / Qwen2.5-VL.
- **`kind: "text" | "vision"` field on `Action`/`ActionSchema`**, defaulted to `"text"` so every existing action and every existing user-defined-action JSON literal stays valid. The runtime dispatches on `action.kind` at the top of `runAction` — vision actions bypass `resolveInput` (which assumes text) and run a separate code path.
- **`picker-replace` output mode** (generic, reusable). Shows N candidates in a new `ChoicePanel` Preact component; on accept writes the chosen value to the block. First user is `image-title`, but the mode is intentionally generic so a future text action could offer "3 grammar correction candidates" or similar.
- **`visionModel` setting**, defaulting to empty. Falls back to `model` when empty so users running a unified Qwen3.5 model leave it blank; users running a smaller text-only model alongside a separate vision model fill it in.
- **Nested outline actions** — `outline-replace` and `outline-append` seed actions. Both use `subtree` scope, read the block + all descendants as LLM input, and parse the model's response into a nested-bullet tree via a new pure `parseOutline` module. `outline-replace` deletes the block's existing children and replaces them with the generated tree (destructive — confirm panel warns). `outline-append` appends the tree under the block, preserving any existing descendants. Both show a preformatted indented preview in a confirm panel before any writes happen.
- **New output modes** `outline-replace` and `outline-append` on `ActionSchema` + the `OutputMode` union. User-defined actions can opt into either mode. The settings-panel user-JSON hint lists the new values.
- **Pure `parse-outline.ts`** — `parseOutline(raw)` builds a tree tolerant of tabs/2-space indent/mixed bullets (- * • 1.), code fences, "Here is the outline:" preambles, over-indented first lines, and skip-level jumps. Anchors the shallowest depth to 0 so an over-indented LLM response doesn't collapse. Helpers: `countOutlineNodes(tree)` and `renderOutlinePreview(tree)` (indented `•` preview for `ConfirmPanel`). 19 new unit tests.
- **Runtime helpers (`src/index.ts`)** — `removeBlockChildren(uuid)` (used by `outline-replace` to wipe existing descendants before insert; `removeBlock` handles the recursion) and `insertOutlineTree(parentUuid, nodes)` (sequential depth-first insert via `logseq.Editor.insertBlock(..., { sibling: false })`, preserves order).

### Fixed

- `image-title` rejecting valid DB-graph image asset blocks. Initial implementation required both the `Asset` tag (matched by `block/title === "Asset"`) AND the raster `asset/type` property. The SDK serialises `block/tags` in several shapes — entity ids, `:logseq.class/Asset` idents, or resolved `[{block/title}]` arrays — and the brittle title match failed on real assets. Fixed by relying on `logseq.property.asset/type` alone (a namespaced property only Logseq's asset infrastructure sets), which is the canonical detection per the logseq-db-plugin-api skill. The runtime warning now also surfaces the asset/type we actually saw and console-logs the block's keys for further debugging if anyone hits a new shape.
- Clear error when no model is configured. Previously, invoking an action with an empty `model` setting produced the opaque `"No content in streamed response"` (which came from the provider after the endpoint returned an empty stream). `runAction` now preflights the setting and shows `AI Actions: no model configured. Open plugin settings and set a model name.` — before any diff panel opens or any HTTP request is made. The diff-panel re-run path also guards, so clearing the model mid-panel surfaces the same reason instead of failing silently inside the stream.

### Changed

- `grammar` prompt tightened to be surgical and Logseq-aware. Old prompt was a one-liner ("Fix grammar, punctuation, and obvious typos") that small local models read as license to rewrite for "better flow." New prompt enumerates the legitimate grammatical-error categories to flag (subject-verb, tense, pronoun, modifiers, prepositions, run-ons, comma splices, parallelism, comparative/superlative, word-form confusions like affect/effect & fewer/less & who/whom) and explicitly forbids flagging note-taking conventions: passive voice, split infinitives, sentence-ending prepositions, contractions, deliberate sentence fragments, lowercase bullet starts. Calls out that the input usually comes from a Logseq block. Preserves quoted material, code blocks, URLs, emails, file paths, `[[wikilinks]]`, `#tags`, proper nouns, technical/domain terminology. Returns text unchanged when it's already correct. New regression test asserts the carve-outs stay in the prompt.
- `spellcheck` prompt tightened to be surgical. Old prompt was a one-liner ("Fix spelling errors") that small local models interpreted loosely — they'd rephrase, fix grammar, "correct" proper nouns. New prompt explicitly forbids changing grammar/style/word choice/punctuation/structure, preserves proper nouns / technical terms / code identifiers / camelCase-ish stylization, and instructs the model to leave URLs, email addresses, Logseq `[[wikilinks]]`, `#tags`, and code-block content alone. Returns the text unchanged when nothing is misspelled. A new regression test (`seed-actions.test.ts`) asserts the carve-outs stay in the prompt so future simplifications can't silently drop them.
- `spellcheck` and `grammar` now default to `outputMode: "diff-panel"` so every text-transform action (spellcheck, grammar, rewrite, summarize) routes through the review panel. User wanted to see and review spellcheck/grammar changes before they land on the block, same as rewrite/summarize. Descriptions updated to mention the review step.
- `summarize` now honours its designed `subtree` scope. Invoking `/AI Summarize` on a block fetches it with `includeChildren: true`, flattens the whole subtree into a Markdown outline via `flattenSubtree`, and sends that as the LLM input. The parent block's text is replaced with the summary; children are preserved as supporting detail (so you keep the source material and gain a TL;DR on top).
- `runAction` refactored around a new `resolveInput(action)` helper that dispatches on `action.scope`. `selection` scope falls back to `block` until the selection-range adapter lands.
- `rewrite` and `summarize` now use `outputMode: "diff-panel"` (their originally-designed output mode). After the model returns, the plugin shows a side-by-side diff with word-level highlights; the user can Accept, Reject, or switch to Edit mode to tweak the proposed text before applying.
- `resolveInput` now returns both `llmInput` (what we send to the model — the flattened outline for subtree scope) and `displayOriginal` (what the diff panel shows as "Original" — the parent block's own text, so subtree scope doesn't produce a useless "every word changed" diff).
- `runAction` branches on `action.outputMode` after the response: `"diff-panel"` invokes `showDiffPanel` and only applies on Accept, `"replace"` writes directly as before.

- `createOpenAIProvider` accepts an optional `fetchImpl` so the transport can be injected. The Logseq adapter wires a `logseqFetch` shim that tries `logseq.Request._request` first (bypasses browser CORS on desktop Electron) and falls back to `globalThis.fetch` on any error. Web Logseq users see no behaviour change; desktop users should stop seeing CORS blocks in most cases.
