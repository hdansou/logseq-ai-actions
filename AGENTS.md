## Dev server

- **`pnpm dev -- --port N` does NOT reliably forward the port flag to Vite.** Use `pnpm exec vite --port N --strictPort` instead. `--strictPort` turns the usual silent fallback into a hard error, which you want because the workspace often has other plugin dev servers squatting 8080/8081/8082 (`logseq-progressbar`, `logseq-atlas`, `Callout Manager`, …). Silent fallback means you end up testing a different plugin without realising.
- **Vite binds to `127.0.0.1`, not `0.0.0.0`.** Logseq loads the bundle from localhost; LAN exposure is unnecessary and would publish every dev iteration to the local network. Pass `--host 0.0.0.0` only when you genuinely need cross-device testing.
- **Don't leave `dist/` on disk while running `vite` in dev mode.** Vite happily serves real files under the project root, so a stale `dist/index.html` from a previous `pnpm build` will be served *instead of* the SPA fallback to root `index.html` — and the stale bundle it references will trigger `[Ready Error] [deferred timeout] undefined` in the plugin iframe. If you ran `pnpm build` for any reason (incl. a pre-commit hook), `rm -rf dist/` before reloading the plugin.
- **`public/` is captured at Vite start.** Adding files to `public/` while Vite is running may not be picked up until restart. If a freshly-added `/foo.png` serves HTML (SPA fallback) instead of the file, restart the dev server.

## Architectural rules

- **Keep the Logseq-touching surface thin.** One adapter module wraps `logseq.Editor.*` / `logseq.App.*`; everything else (registry, scope resolver, endpoint classifier, diff, streaming parser) stays pure so Tier 1 unit tests can reach it. The 80 % coverage gate is only achievable under this rule — a PR that thickens the adapter without a compelling reason should be pushed back on.
- **Only `src/index.ts` does `import "@logseq/libs"`.** Every other module that needs the `logseq` global uses `/// <reference types="@logseq/libs" />` for types only. Vitest crashes on the SDK's browser-only bootstrap (`ReferenceError: self is not defined`) otherwise — see the `logseq-plugin-dev` skill's `runtime-gotchas.md §11`.
- **SDK pinned via the `next` dist-tag at `^0.3.2`.** Public npm `latest` points at the legacy `0.0.17` line. Do not run `pnpm update @logseq/libs` without checking the dist-tag.
- **Plugin iframe is cross-origin with the Logseq main window — any synchronous `parent.window.logseq.…` access throws `SecurityError`.** The plugin runs at `lsp://logseq.io/...`; the Logseq main window is at a different origin in current builds. This breaks `logseq.Request._request`, `logseq.Experiments.invokeExperMethod`, and anything else that uses `ensureHostScope()`. The Postmate-based caller (`logseq/libs/src/LSPlugin.caller.ts`) uses `window.postMessage`, which IS cross-origin-safe — that's how slash commands, settings, and event registration work. For SDK-internal API calls, use `logseq._execCallableAPIAsync(method, ...args)` (postMessage path, internal) instead of `logseq.Experiments.invokeExperMethod` (host-scope path, broken).
- **Loading raw bytes for an asset path: postMessage `:readFileRaw` IPC, not `:httpRequest` and not `fetch`.** `logseq.Assets.makeUrl` returns `file:///abs/path` on Desktop, `blob:` on Web. From the plugin iframe `fetch(file://)` and `<img src="file://">` are blocked by Chromium. `Request._request` is broken (cross-origin host scope, see above). `:httpRequest` is also wrong for `file://` because Logseq pins `node-fetch@3.3.2` which dropped `file://` support. The working call is `logseq._execCallableAPIAsync("doAction", ["readFileRaw", absPath, "js-obj"])`. The snake-case lookup chain in `logseq/libs/src/common.ts:invokeHostExportedApi` resolves `"doAction"` to `window.apis.doAction`, which IPCs to the main-process dispatcher. The dispatcher does `(keyword (first args))` so the keyword string `"readFileRaw"` (NO leading colon — `(keyword ":readFileRaw")` in cljs preserves the colon as a name character and dispatch falls through) matches `defmethod handle :readFileRaw` (`handler.cljs:79`) → `fs.readFileSync(path)` → Buffer. See `src/adapter/image-loader.ts:tryReadFileRawIPC`.
- **`doAction` IPC returns are transit-encoded by default — pass `"js-obj"` as the trailing flag to get raw JS.** `set-ipc-handler!` (`logseq/src/electron/electron/handler.cljs:531`) inspects the message: if its last item keywordises to `:js-obj` it returns `(bean/->js result)`, otherwise `(sqlite-util/write-transit-str result)`. Without the flag, a Node Buffer comes back as the string `["~#'", "~b<base64>"]` and structural type checks (`instanceof Uint8Array`, etc.) all fail silently. With the flag, Buffer (a `Uint8Array` subclass) survives Postmate structured-clone intact. Pre-flight check when designing a new IPC call: probe the return shape via `_execCallableAPIAsync('doAction', […])` in the plugin frame's DevTools console BEFORE writing decoder code — the wire format is not what the cljs handler returns.
- **The SDK `.d.ts` understates what's available — read Logseq's cljs source instead.** v1.0.1 shipped fetch + `<img>+canvas` assuming `IAssetsProxy` was the only file-I/O surface. v1.0.2 used `Request._request`. v1.0.3 added diagnostics. v1.0.4 found the postMessage caller. v1.0.5 found `:readFileRaw`. v1.1.1 corrected the keyword colon convention. v1.1.2 added the `"js-obj"` flag. Each iteration was avoidable by reading `/Users/dzu/Projects/src/github.com/logseq/libs/src/LSPlugin.caller.ts`, `.../src/main/logseq/api.cljs`, and `.../src/electron/electron/handler.cljs` upfront, AND by probing the IPC return shape in DevTools before writing decoder code — the SDK surface is much smaller than the Electron IPC surface, and the wire format around that surface is not documented in the `.d.ts` at all. Grep cljs before designing; probe DevTools before decoding.
- **After changing plugin code, disable + re-enable the plugin in Logseq settings.** Slash-command / palette / context-menu / toolbar handlers are registered at plugin-enable time and capture a reference to the module they were loaded with — Vite HMR rebuilds the bundle but the running handler still points at the old module. Symptom: a fix you just shipped doesn't appear (e.g., a refactored toast still shows the old string). Cmd+R on Logseq's window also works but is heavier.
